# 存档结构与恢复

数据库仍为 IndexedDB `gulu-expedition`，对象表 `save`，数据库版本与 `schemaVersion` 均保持1。单文件游戏与导出JSON的主存档结构兼容原版。

## 存储槽

| 键 | 内容 | 更新规则 |
|---|---|---|
| main | 玩家主存档 | 关键操作后约250ms防抖保存；写入串行，事务完成才认定成功 |
| backup | {savedAt, reason, state} | 成功导入、重置、恢复前，将当前好档与新main在同一个事务中提交 |
| rejected | {savedAt, reason, raw} | 损坏/不兼容main经用户确认替换时，先在同一事务保留原始数据 |

backup只有一份。普通自动保存不覆盖它；下一次成功的导入/重置/恢复会更新它。rejected也只保留最近一次被替换的异常原档，不是无限历史。

## 校验与迁移

主存档包含资源、英雄/碎片、装备、五人编队/三预设、主线/塔/副本、计数/任务/签到/邮件、招募保底、挂机、设置/剧情，以及商城/外观/赛季/竞技场/迷雾远征。

加载和导入均经过原始结构校验 → 深层默认值合并 → 合并结果校验。必要进度字段缺失时拒绝载入，不把残缺对象当作新档。允许schema1旧档缺少后来新增的商城、外观、活动、竞技场、远征字段，或缺少部分设置/新增资源字段；按默认值补齐，不修改输入对象、不共享引用、不补发默认英雄。未知schema保留原档并进入恢复页。

检查包括有限数值/整数/非负资源、英雄与技能/星级范围、编队与预设长度/唯一性/拥有关系、装备UID/归属/部位/品质/属性/同部位重复穿戴、关卡与副本星级/次数、日期/时间戳、保底、邮件、地图型领取标记、外观/活动、战绩、远征生命/遗物与进行态，以及模拟钱包结构。

允许装备属性、生命比例与挂机余数为合法小数；钱包流水和战绩积分变化允许负值。导入文字不接受HTML标签分隔符，关键标识仅接受字母、数字、下划线与连字符；拒绝原型相关键和循环结构。JSON文件上限5 MiB，结构最多40层/200000节点，避免异常大文件阻塞。校验属于客户端健壮性保护，不是服务端防作弊，也不校验全部玩法资格。

## 导入、重置与恢复

先校验候选档，再显示确认；确认前不修改当前进度。确认后短暂禁止游戏交互，将当前快照与候选档放入一次事务。失败时两者都不覆盖，当前内存进度不变，可重试；成功后才切换内存与页面。先前排队的自动保存先完成，不能在导入后写回旧档。进行中或尚未关闭的战斗禁止替换存档。

设置提供：导出当前存档、导入、恢复上次备份、导出备份、重置，以及导出保留的异常原档。恢复会把被替换的当前好档保留为下一份backup。

启动区分没有main、读取失败、main损坏/版本不兼容。只有没有main时自动创建新档。后两种进入恢复页，暂停自动保存，提供重试、导出原档、恢复备份和导入；明确确认重新开始时也先保留已读到的异常原档。未能读取原档时禁止覆盖，需先重试读取。

导出当前内存的JSON不依赖IndexedDB写入成功，便于存储不可用时留文件备份。切后台/pagehide尽力保存，浏览器强制结束不保证完成。

## 日期与边界

每日重置仍按Asia/Shanghai游戏日执行；副本、竞技场、签到及商城领取规则不变。系统时钟回拨时挂机新增时长最低为0，避免出现负收益。

备份与主档都在同一浏览器/来源下；更换域名/端口、清除站点数据、卸载浏览器时不能依赖本机备份，跨设备仍需导出文件。写入队列只协调当前页面，未实现多标签页冲突检测、云端恢复或事务完成后的物理断电持久性保证。
